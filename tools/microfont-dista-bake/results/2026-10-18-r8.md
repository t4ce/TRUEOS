# Physical Dista R8 mask versus RGBA8 — 2026-10-18

The physical Intel iGPU (`8086:4680`) completed **384 atlas renders** across two matched matrices. Direct R8 output uses **75% less target storage** and produced identical coverage to RGBA8 in every pixel of all 24 validation pairs. **GPU generation time did not improve:** Fine/direct needs approximately **21.261 ms for both weights** in either format.

This implements a color-independent coverage target for the experiment. The Dista vertex shader and triangle geometry are unchanged. It does not replace a font consumer, add a scanout format, compose colors, or integrate a CPU/BCS0 sink. Every warm sample rebuilds the atlas; retained-atlas copies were not measured.

Each 1536 × 1056 atlas holds 95 Basic Latin slots (`U+0020..U+007E`, including blank space) at 96 × 176 pixels per glyph. Both formats use white ink, zero clear, the same four hardware timestamp markers, and PAT3/UC render-target aliases. R8 is the actual render target; no RGBA-to-R8 conversion pass runs.

| Format | Bytes per atlas | Row pitch | Bytes for Meso + Lean |
| --- | ---: | ---: | ---: |
| RGBA8 | 6,488,064 | 6,144 | 12,976,128 |
| R8 coverage | 1,622,016 | 1,536 | 3,244,032 |

R8 saves **4,866,048 bytes per atlas**, or **9,732,096 bytes for both weights**. Coverage is binary (zero or 255) in the current Dista producer; this experiment does not add antialiasing. Color and opacity remain available for a later composition step.

**Clear/setup remains approximately 8.173 ms per atlas in both formats**, about 77% of Fine’s complete GPU interval. Final writeback remains approximately 9 µs. Reducing storage to R8 does not remove that bottleneck; this result does not isolate the clear operation from its state setup. The 0.000052 ms difference between pooled Fine/direct target-ready totals is too small to support a speedup claim.

First-use host wall time improved, with these separately measured Fine/direct totals for Meso and Lean:

| Matrix | RGBA8 first-use | R8 first-use |
| --- | ---: | ---: |
| 1 | 61.737889 ms | 48.082977 ms |
| 2 | 61.629882 ms | 47.328338 ms |

The median per-atlas allocation interval in Fine/direct was **11.712 ms for RGBA8** and **3.750 ms for R8** across both weights and runs. Task preparation and upload stayed near 1.87 ms and 2.24 ms. These first-use wall measurements include different allocation and ownership paths (UI4 frame versus dedicated mask); they establish an observed end-to-end improvement, not a format-only GPU speedup. Warm host wall times vary with live scheduling and do not give a stable format ranking.

All **24 full-image comparisons passed**, checking **38,928,384 pixel pairs** after the timed bursts. Every R8 byte matched RGBA coverage; all four RGBA channels agreed, every coverage byte was zero or 255, all 94 nonblank glyph slots contained ink, and the space and unused final slot remained blank. Every geometry count and upload size matched between formats. There were no benchmark errors or missing GPU timestamps. All 48 configurations released their mesh and target; phase intervals sum to target-ready within 2 ns of timestamp rounding. Pixel validation, cache flushing, snapshots and comparison allocation are outside every timed interval.

GPU target-ready includes clear, procedural vertex expansion, rasterization and ordered target writeback. Host wall time also includes preparation, queueing and release-cookie waiting. Neither scope includes color composition, scanout or a CPU/BCS0 sink. The four markers match the previous atlas experiment; vertex and raster work overlap within the body interval.

Ordinary `make iso` includes the experiment and the existing GPU-menu entry `dista-bench 7`. The tested build used `make iso PUBLISH_RELEASE_SMB=0`; physical reset and the booted image identity were verified.
