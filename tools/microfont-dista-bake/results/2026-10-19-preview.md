# Full Meso atlas preview — 2026-10-19

The UI4 specimen now shows all 95 printable Basic Latin slots in Meso. GLSL
generates a retained R8 mask; the CPU copies coverage into the visible RGBA
frame once per selected view. There is no CPU glyph reconstruction. Cached
sources require no further GPU generation, and idle views do no painting.
Existing font consumers are unchanged.

Select the atlas frame and use:

- `Q`: circle segments 4, 8, 12, 16, 24.
- `A`: toggle a 2× GPU mask in both axes, resolved by a 2×2 average during the CPU copy.
- `1`–`5`: glyph sizes 6×11, 12×22, 24×44, 48×88, 96×176.
- `+` / `-`: step between sizes. Escape closes the frame.

The default is 96×176, 16 segments, AA off. The final frame is placed left of
the companion overlay so the complete atlas remains unobstructed.

Physical tests exercised 17 views, every size and every quality setting.
There were 12 GPU generations and five cache hits; each hit performed zero
GPU generation and one CPU copy. Every view logged exactly one CPU copy and
zero CPU geometry. Ten seconds idle produced no additional copies. The final
verified boot independently rendered once, copied once, and remained idle
for another ten seconds. GPU status showed no failures or faults.

These are individual N16 observations, not a repeated timing benchmark:

| Glyph size | AA | GPU clear through mask ready | CPU copy/resolve |
| --- | --- | ---: | ---: |
| 96×176 | off | 11.197 ms | 32.264 ms |
| 96×176 | 2× | 42.220 ms | 38.057 ms |
| 24×44 | off | 1.307 ms | 2.377 ms |
| 24×44 | 2× | 3.250 ms | 2.834 ms |

AA produced 41,105 partially covered pixels at 96×176 and 10,261 at 24×44.
It changes sampling coverage, while polygon quality independently controls
the chord error. At 24×44, N8 bounds that geometric error to approximately
0.106 px; at 96×176, N16 gives approximately 0.107 px. These are geometric
bounds, not a determination of the visually preferred setting.
