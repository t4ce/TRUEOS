AP / CPU slots

APs are CPU slots. Start nodes spawn tokens; the round-robin scheduler dispatches up to AP count tokens per SMP tick. The lens only changes how you read the same graph.

Tiny model

Mutex: one owner or free. If busy, lockers queue. Only the owner may unlock. Semaphore: integer permits. wait consumes one or blocks. post wakes one waiter or adds a permit. No owner. Spawn / Join: Spawn creates a child thread on its dashed child edge; the parent follows the normal edge. Join waits for a child handle from the same parent. Condition variable: Wait C/M requires owning mutex M, atomically unlocks M and sleeps on C. Signal wakes one waiter; Broadcast wakes all. Woken waiters must re-lock M before continuing. Barrier: N tokens must arrive at the same barrier generation before all are released together. Yield: cooperative scheduling point. The token advances, but visually marks a place where a Tokio task would give the worker back to the runtime. Park N: token becomes not-ready until a future scheduler tick. Read it as sleep/timer/awaited event; it does not consume an AP slot while parked. SMP tick: a round-robin scheduler chooses up to AP-count ready tokens from a start-of-tick snapshot. Lock/semaphore conflicts are resolved in dispatch order. Work node: can take N scheduled micro-steps per thread. Scenario increment counter is non-atomic: first step reads, final step writes. Each token shows per-node progress like 1/3.

Things to try

Race: press SMP tick until both APs read counter=0 in the same tick, then both write. Mutex: AP1 blocks while AP0 owns M. Semaphore: set default S permits to 1, 2, or 0 and reset. Spawn/join: normal edge is the parent; dashed edge is the child path. Condvar: try Signal before Wait to see that condition variables do not store permits. Barrier: lower AP count to see arrivals spread over scheduler ticks. Yield/Park: use Yield to mark cooperative handoff; use Park N to make a token sleep without occupying an AP slot. Work duration: select a Work node and change Steps to 3 or 5.
